⚙️  Набір команд zenity

Розділ Що виконує команда Синтаксис Bash
🛠️ Частина 1. Набір команд zenity
1. Попередження (Кнопка "ОК") Використовується, щоб показати помилку або важливе повідомлення. 
zenity --warning --title="Увага!" --text="Батарея майже розряджена!"
2. Вибір дати (Календар) Виводить інтерактивний календар. Коли користувач вибирає дату, вона повертається у форматі ДД.ММ.РРРР 
zenity --calendar --title="Виберіть день" --text="Коли дедлайн?"
3. Вибір файлу на комп'ютері Відкриває стандартне системне вікно провідника. Повертає повний шлях до вибраного файлу. 
zenity --file-selection --title="Виберіть шлях до файлу"
4. Шкала прогресу (Індикатор завантаження) Показує повзунок, що заповнюється від 0 до 100%. Дуже круто для довгих скриптів. 
( echo " 10 " ; sleep 1 echo " 50 " ; sleep 1 echo " 100 " ; sleep 1 ) | zenity --progress --title="Копіювання" --text="Будь ласка, зачекайте..." --percentage=0 --width=600 --height=100
📦 Частина 2. Мінімальний набір роботи зі Змінними
У Bash змінні - це дуже просто, але потрібно суворо дотримуватися двох правил: 1. Записати текст або число вручну: 
NAME="Олексій" AGE=30
При записі НЕМАЄ знака долара і НЕМАЄ пробілів навколо = Записати в змінну результат роботи zenity: 
# Обов'язково використовуємо $( ... ) навколо команди MY_FILE=$(zenity --file-selection)
Під час читання (виклику) знак долара ОБОВ'ЯЗКОВИЙ. Використовувати змінну у тексті: 
# Переменная внутри двойных кавычек автоматически превратится в свое значение zenity --info --text="Привет, $NAME! Тебе уже $AGE лет."
🧠 Частина 3. Мінімальний набір умов if (Логіка)
Умови дозволяють скрипту ухвалювати рішення.(Зверніть увагу: усередині квадратних дужок [...] пробіли після першої дужки і перед останньою обов'язкові!). Перевірка кнопки Так / Ні (через zenity --question) 
if zenity --question --text="Ви впевнені?"; then
zenity --info --text="Відмінно, продовжуємо!"
else
zenity --info --text="Процес скасовано."
exit 0 # Вихід зі скрипту
fi
Дуже важлива перевірка. Прапор -z перевіряє, чи не порожня змінна. Якщо користувач натиснув "Скасувати" у вікні введення, змінна буде порожньою, і скрипт може зламатися. Захищаємо його: Перевірка: «А чи ввів користувач хоч щось?» 
USER_INPUT=$(zenity --entry --text="Введіть кодове слово:")

if [-z "$USER_INPUT"]; then
zenity --error --text="Ви нічого не ввели або натиснули Скасувати!"
exit 1
fi
Якщо потрібно порівняти числа (наприклад, введений час), використовуються спеціальні скорочення: -gt (Greater Than) - більше > -lt (Less Than) - менше < -eq (EQual) - дорівнює = Порівняння чисел 
CHAIRS=5

if [ "$CHAIRS" -gt 3 ]; then
    zenity --info --text="Стільців більше, ніж три!"
fi

💫  про GitHub

🪎  Як отримати посилання на сайт, якщо файл index.html завантажив на GitHub


1) Зайти на сайт, GitHub Pages,у розділ, куди був завантажений файл
2) У верхньому меню (під назвою репозиторію) знайди та натисні на вкладку Settings (Налаштування) зі значком шестерні ⚙️
3) Перейти в розділ Pages лівого бічного меню.
4) Вкажи гілку для збирання. В розділi Build and deployment, у підрозділі Source у списку, що випадає, слід вибрати Deploy from a branch.
Трохи нижче, у графі Branch, треба зміни значення None на main (або master – залежно від того, як називається основна гілка).
Папку поруч залиш за замовчуванням – / (root).
5) Залишається стерегти налаштування натиснувши кнопку Save (Зберегти).
6) Де шукати саме посилання?
– Після натискання кнопки Save сторінці знадобиться близько 1-2 хвилин на складання.
Потім потрібно оновити сторінку налаштувань Pages.
У самому верху з'явиться плашка з текстом: "Your site is live at..." - це і є пряме посилання на сайт!
Зазвичай вона виглядає так: https://[ім'я-користувача].github.io/[назва-репозиторія]/
Важливий момент: файл обов'язково має називатися строго маленькими літерами "index.html".
Якщо назвати його Index.html або main.html, GitHub не зрозуміє, яку сторінку відкривати першою, та видасть помилку 404.

Коли будуть вноситись зміни до коду або завантажуватиметься оновлений "index.html", адреса сайту залишиться незмінною.
Однак є пара важливих нюансів, про які варто пам'ятати під час оновлення: затримка в 1–2 хвилини: після того, як завантажиться нова версія файлу, зміни на сайті з'являться не миттєво. GitHub потрібно трохи часу, щоб перезiбрати сторінку.
Кеш браузера: якщо завантажилися оновлення, пройшло пару хвилин, ти переходиш за посиланням, а сайт все ще старий – швидше за все браузер закешував попередню версію. Просто онови сторінку жорстко: Ctrl+ F5 (Windows) або Cmd + Shift + R (Mac). Якщо вирішиш додати на сайт стилі, картинки або скрипти, просто закидай їх у цей репозиторій, і все буде працювати.

Омніканальність

   У сучасному динамічному світі, де технології проникають у всі сфери нашого життя, ми більше не задовольняємося розрізненими точками контакту із сервісом чи документом.
 Саме тут на сцену виходить
Омніканальність
- це стратегія, що поєднує різні канали комунікації в єдину безшовну екосистему.

 Омніканальна стратегія дозволяє використовувати інформацію як робочий інструмент.  Переваги омніканальності незаперечні.

Створенням цього проекту я намагався якось організувати традиційний хаос як серед моїх "інформаційних потреб", так і різноманітних сканів, документів, фотографій тощо.
